# 큐레이팅 설계 — 현황 & 로드맵

뉴스 수집과 큐레이팅의 차이, 현재 구현 수준, 그리고 심층 리서치로 가는 단계별 로드맵을 정리한다.

---

## 수집 vs 큐레이팅

> [!info] 핵심 차이
> **수집**은 인터넷에서 데이터를 당겨오는 것이고, **큐레이팅**은 그 데이터를 내 투자 논리에 비추어 거르고 맥락을 붙이는 것이다.

| | 뉴스 수집 | 큐레이팅 |
|---|---|---|
| 질문 | "무엇이 있는가?" | "내게 의미 있는 것은 무엇인가?" |
| 필터 기준 | 키워드 (회사명, ticker) | 볼트 투자 메모 (벡터 유사도) |
| 출력 | 기사 목록 + 스니펫 | 테마 그룹핑 + 투자 시사점 |
| 저장 위치 | `News/YYYY-MM-DD.md` | `Curated/YYYY-MM-DD.md` |

---

## 현재 큐레이팅 구조

`Curated/` 파일은 6개 섹션으로 구성된다.

### ## 오늘의 핵심 테마
수집된 뉴스를 2~4개 주제로 묶어 각 테마에서 무슨 일이 있었는지 요약한다.

### ## 투자 시사점
오늘 테마가 내 투자 thesis에 어떤 의미인지 3~5개 불릿으로 분석한다.
단순 요약이 아니라 "무엇이 바뀌었고, 포지션에 어떤 의미인가"를 명시한다.

### ## 논거 검증
투자 thesis가 오늘 뉴스로 **강화됐는지 / 유지됐는지 / 약화됐는지** 한 문장으로 판단한다.
어떤 thesis 항목이 영향을 받았는지 구체적으로 명시한다.
확신 강도를 날짜별로 추적할 수 있는 기반이 된다.

### ## 리스크 업데이트
**오늘 뉴스에서 새로 부각된 리스크**만 기재한다. 기존에 알려진 항목은 제외.
오늘 처음 등장하거나 기존 대비 악화된 것만 — 변화를 추적하는 것이 목적이다.

### ## 모니터링 포인트
오늘 뉴스에서 도출된 향후 확인 사항이다.
- 예: 실적 발표일, 규제 결정 예정일, 다음 분기 지표, 경쟁사 발표

### ## 경쟁사/섹터 동향
경쟁사 및 섹터 뉴스 중 **이 회사에 직접 영향을 주는 것**만 기재한다.
단순 나열이 아니라 "이 회사에 어떤 의미인가"를 명시한다.
- 예: "테슬라 가격 인하 → 현대차 EV 마진 압박 심화"
- 예: "Micron HBM 공급 증가 → 삼성전자 점유율 경쟁 심화"

## 섹션별 역할 비교

| 섹션 | 질문 | 성격 |
|------|------|------|
| 오늘의 핵심 테마 | 오늘 무슨 일이 있었나? | 사실 요약 |
| 투자 시사점 | 포지션에 어떤 의미인가? | 판단 |
| 논거 검증 | 내 thesis가 맞고 있는가? | 자기 점검 |
| 리스크 업데이트 | 오늘 새로 생긴 위험은? | 변화 추적 |
| 모니터링 포인트 | 다음에 무엇을 봐야 하나? | 액션 아이템 |
| 경쟁사/섹터 동향 | 주변 환경이 어떻게 변했나? | 맥락 |

## 현재 시스템의 한계

> [!warning] 분석 품질의 구조적 제약

| 항목 | 현재 상태 | 한계 |
|------|---------|------|
| 뉴스 내용 | 제목 + 스니펫 (50~200자) | 기사 본문 미독 |
| 분석 모델 | `gemma4:e2b` (7B, 로컬) | 추론 깊이 제한 |
| 재무 데이터 | 없음 | 정량 분석 불가 |
| 과거 참조 | 없음 | 변화 추적 불가 |
| 언어 | KRX: 한국어 / 해외: 영어 | 교차 분석 약함 |

## 심층 리서치 로드맵

\`\`\`
현재 ──────── 1단계 ──────── 2단계 ──────── 3단계
 │              │               │               │
스니펫만       본문 읽기      재무 결합       과거 비교
(제목+200자)  (기사 전문)   (주가/PER/매출)  (thesis 변화)
\`\`\`

### 1단계 — 기사 본문 스크래핑 (비교적 쉬움)

CLAUDE.md Phase 3에 설계된 `src/scraper/` 구현.
BeautifulSoup으로 본문 추출 → 실패 시 Playwright 폴백.

**효과:** 스니펫 대비 분석 컨텍스트 5~10배 증가.
**제약:** 페이월 기사 접근 불가.

### 2단계 — 재무 데이터 결합 (중간)

Yahoo Finance에서 주가, PER, 매출 성장률, 52주 범위 등을 수집해 큐레이팅 프롬프트의 컨텍스트에 포함한다.

**효과:** "주가가 오늘 3% 하락했고 현재 PER 15배 — 역사적 저점 근처" 같은 정량 판단 가능.

### 3단계 — 과거 큐레이팅 비교 (중간)

`Curated/` 폴더에 날짜별 파일이 축적되면, 오늘 분석을 지난주/지난달과 비교한다.

**효과:**
- "2주 전 대비 파업 리스크 악화"
- "HBM 공급 우려가 3회 연속 언급 → 핵심 변수로 격상"

## 모델 선택 가이드

> [!note] 로컬 vs API

| 용도 | 모델 | 이유 |
|------|------|------|
| 현재 (기사별 판정, 근거 한 문장) | `gemma4:e2b` (로컬) | 빠름, 무료, 단순 작업에 충분 |
| 심층 분석 (본문 전체 읽기, 재무 해석) | `claude-sonnet-4-6` (API) | 긴 컨텍스트, 복잡한 추론 필요 |
| 큐레이팅 종합 (현재) | `gemma4:e2b` (로컬) | 구조화 출력, 비용 없음 |
| 큐레이팅 종합 (고품질 목표) | `claude-sonnet-4-6` (API) | 분석 깊이 급격히 향상 |

실질적 심층 리서치(SEC 파일링, 경쟁사 교차 분석, 복잡한 수치 추론)는
**로컬 7B 모델의 한계**를 넘어선다. Claude API 연동이 가장 현실적인 해결책이다.
