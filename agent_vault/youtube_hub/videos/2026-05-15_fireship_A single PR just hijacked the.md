# A single PR just hijacked the NPM registry...

## 핵심 요약 (3줄)
1.  최근 오픈소스 npm 생태계에서 CI/CD 파이프라인의 `pull_request_target` 설정 취약점을 악용, 수백 개의 패키지가 감염되고 배포 토큰이 탈취되는 심각한 공급망 공격이 발생했습니다.
2.  악성코드는 감염 시스템에서 추가 토큰을 훔쳐 빠르게 확산되었으며, GitHub 토큰 만료 시 사용자 홈 디렉터리를 삭제하는 "데드맨 스위치" 기능까지 포함했습니다.
3.  PNPM 1 이상 버전의 '최소 배포 연령', '외부 서브 의존성 차단', '승인된 빌드' 기능 등을 통해 유사한 유형의 공격을 효과적으로 예방할 수 있습니다.

## 타임스탬프별 핵심
- **공격 개요 및 심각성** — npm 오픈소스 생태계에서 5천만 회 이상 다운로드되는 100개 이상의 패키지가 공급망 공격에 노출되었으며, 신뢰할 수 있는 발행 기능마저 우회당했습니다.
- **공격 방식 상세 분석** — Tanstack 저장소의 `pull_request_target` GitHub Actions 설정 미비점을 이용하여 포크된 PR이 메인 저장소의 권한으로 실행, CI 캐시에 악성코드를 주입하고 npm 배포 토큰을 탈취했습니다.
- **악성코드 확산과 고도화** — 탈취한 토큰으로 다른 패키지들을 감염시키고 Python PyPI 생태계로도 확산되었으며, AI 생성 커밋으로 위장하고 개발자 에디터에 내장되어 지속적으로 재실행되는 등 고도화된 전파 전략을 보였습니다.
- **파괴적인 데드맨 스위치** — 감염된 시스템에서 GitHub 토큰의 유효성을 60초마다 확인하여, 토큰 만료 시 사용자 루트 디렉터리를 삭제하는 "워 크라임 모드"가 발동되도록 설계되었습니다.
- **효과적인 예방 및 보안 강화** — PNPM 1 이상 버전의 '최소 배포 연령' (24시간 이내 발행 패키지 거부), '외부 서브 의존성 차단' (비공식 레지스트리 의존성 차단), '승인된 빌드' (설치 스크립트 기본 차단 및 화이트리스트 방식) 기능을 통해 이러한 공격을 방지할 수 있습니다.
- **Sentry의 AI 기반 문제 해결** — Sentry의 Seir Agent는 프로덕션 문제를 AI가 자동으로 조사하고 근본 원인을 찾아 수정 제안까지 제공하여, 개발자들이 에러 트러블슈팅에 소요되는 시간을 줄일 수 있도록 돕습니다.

## 투자/개발 시사점
> 오픈소스 소프트웨어 공급망의 취약성은 기업의 핵심 자산에 직접적인 위협이 되므로, 보안 검토와 투자는 이제 필수입니다. 투자자들은 공급망 보안 및 개발자 생산성 향상 솔루션 제공 기업에 주목해야 하며, 개발자들은 CI/CD 파이프라인의 보안 설정(특히 `pull_request_target` 같은 트리거)을 철저히 검토하고 PNPM과 같은 보안 기능이 강화된 도구를 적극 도입해야 합니다.

- AI 기반 개발자 생산성 및 에러 모니터링 플랫폼 (예: Sentry)
